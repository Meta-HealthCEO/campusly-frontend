# Module 4 — Homework: Production-Ready

**Date:** 2026-05-09
**Owner:** Shaun Schoeman
**Status:** Approved (proceeding to implementation plan)

---

## 1. Goal

Make Campusly's homework workflow production-ready end-to-end: teachers assign structured homework via a wizard, students submit type-specific answers, AI auto-grades open-ended questions, results land in the gradebook, and parents see status without logging in to a separate surface.

This module hardens existing surface — the `Homework` backend module, structured discriminated-union types, and partial teacher/student/parent pages already exist. The work is finishing flows, replacing free-text leakage with structured submissions, wiring auto-grading, and unifying parent visibility.

## 4. Data model changes

### 4.1 `Homework` (extend existing)

**Add:**
```ts
latePolicy: 'block' | 'penalty' | 'accept';   // default 'block'
latePenaltyPercent?: number;                  // 0-100, used when latePolicy='penalty'
comprehensionQuestionIds?: Types.ObjectId[];  // only set when type='reading'; refs QuestionBank.Question
gradebookAutoPublish: boolean;                // default true
assessmentId?: Types.ObjectId | null;         // cached link, lazy-set on first publish
version: number;                              // default 1, bumped on edits (mirrors AssessmentPaper pattern)
```

**Remove (currently in schema, never wired):**
```ts
peerReviewEnabled
groupAssignment
maxFileSize
allowedFileTypes
```

Migration: existing records auto-default `latePolicy='block'`, `gradebookAutoPublish=true`, `version=1` (Mongoose populates defaults on read for fields absent in old docs). Removed fields persist as ghost fields on existing documents in MongoDB but are inaccessible from the TypeScript interface and not written by future updates. Optional follow-up cleanup migration can `$unset` them later — not required for Module 4.

### 4.2 `HomeworkSubmission` — discriminated union

**Replace** the current generic `files: string[]` shape with three variants on a shared base.

**Shared base (`HomeworkSubmissionBase`):**
```ts
homeworkId: ObjectId;
studentId: ObjectId;
schoolId: ObjectId;
homeworkVersion: number;            // snapshot at submission time
submittedAt: Date;
isLate: boolean;
gradingStatus: 'pending' | 'graded' | 'failed';
mark?: number;                       // total awarded after late penalty
maxMarks: number;                    // snapshot from homework
feedback?: string;
gradedAt?: Date;
gradedBy?: ObjectId | null;          // teacher User._id when manually graded; null for auto-graded
gradingGeneration: number;           // increments on each (re)submission; async grader checks this before writing
errorMessage?: string;               // populated when gradingStatus='failed'
lateMarkAdjustment?: {               // audit trail of late penalty calculation
  rawMark: number;
  penaltyPercent: number;
  finalMark: number;
};
```

**Variants:**

`QuizSubmission` (`type: 'quiz'`):
```ts
answers: Array<{
  questionIndex: number;             // index into Quiz.questions
  questionSnapshot: string;          // snapshot of questionText at submit time
  studentAnswer: string;
  awarded?: number;
  maxMarks: number;                  // snapshot from quiz.questions[i].points (Quiz model uses 'points', map to 'maxMarks')
  rationale?: string;                // AI rationale for non-deterministic grades
  gradingMethod: 'deterministic' | 'ai' | 'teacher' | 'pending';
}>;
```

`ExerciseSubmission` (`type: 'exercise'`):
```ts
answers: Array<{
  questionId: ObjectId;              // ref QuestionBank.Question
  questionSnapshot: string;          // snapshot of stem at submit time
  studentAnswer: string;
  awarded?: number;
  maxMarks: number;
  rationale?: string;
  gradingMethod: 'deterministic' | 'ai' | 'teacher' | 'pending';
}>;
```

`ReadingSubmission` (`type: 'reading'`):
```ts
markedReadAt: Date;
comprehensionAnswers: Array<{
  questionId: ObjectId;              // ref QuestionBank.Question
  questionSnapshot: string;
  studentAnswer: string;
  awarded?: number;
  maxMarks: number;
  rationale?: string;
  gradingMethod: 'deterministic' | 'ai' | 'teacher' | 'pending';
}>;
```

**Indexes** (preserve existing + add):
```ts
{ homeworkId: 1, studentId: 1 } unique  // existing
{ studentId: 1 }                         // existing
{ schoolId: 1, gradingStatus: 1 }        // NEW — for status polling queries
{ homeworkId: 1, gradingStatus: 1 }     // NEW — teacher detail page
```

### 4.3 No new collections

Comprehension questions live in the existing `QuestionBank.Question` collection with `source='ai_generated'`, `status='approved'`, `schoolId` set, and the homework references them via `comprehensionQuestionIds`.

## 5. Backend services

### 5.1 `service-homework-grading.ts` (NEW, target ≤300 lines)

type DeterministicResult = { awarded: number; rationale: string };
type AIResult = { awarded: number; rationale: string };

// Deterministic graders — no AI, instant return
function gradeMcq(question, studentAnswer): DeterministicResult;
function gradeTrueFalse(question, studentAnswer): DeterministicResult;
function gradeFillBlank(question, studentAnswer): DeterministicResult;
  // normalize: trim, lowercase, collapse whitespace, strip punctuation

// AI grader — calls Claude
async function gradeWithAI(
  question: { stem, answer, markingRubric, marks, type },
  studentAnswer: string,
): Promise<AIResult>;

// Top-level: grades a single answer based on question type
async function gradeAnswer(question, studentAnswer): Promise<{
  awarded: number;
  rationale: string;
  gradedBy: 'deterministic' | 'ai';
}>;

// Async fire-and-forget — grades AI-typed answers, updates submission doc
async function gradeSubmissionAsync(submissionId: ObjectId): Promise<void>;
  // 1. Load submission, find all answers where gradedBy is unset
  // 2. Cap concurrency at 3 — Promise.allSettled chunked
  // 3. On all complete: set gradingStatus='graded', mark = sum of awarded
  //    apply late penalty per homework.latePolicy
  // 4. On any throw: set gradingStatus='failed', errorMessage

## 10. Auto-grading flow detail

```
Student clicks Submit
        │
        ▼
POST /homework/:id/submit
   { type-specific answers }
        │
        ▼
Backend: validate payload shape against homework.type
        │
        ▼
For each answer:
  if question.type ∈ {mcq, true_false, fill_blank}:
    grade synchronously, store {awarded, rationale, gradedBy: 'deterministic'}
  else:
    leave awarded undefined, gradedBy will be set later
        │
        ▼
Compute partial mark (sum of deterministic awards), set on submission
        │
        ▼
Are there ungraded answers? ──── No ──→ gradingStatus='graded',
        │                                applyLatePenalty(),
        │                                publishHomeworkGrade()
        │                                Return submission to client
       Yes
        │
        ▼
gradingStatus='pending', save submission
Fire-and-forget: gradeSubmissionAsync(submissionId)
Return submission to client
        │
        ▼
Client renders submission with "Grading..." for ungraded Qs
Client polls GET /homework/submissions/:id every 3s
        │
        ▼
Async grader: for each ungraded answer, call gradeWithAI()
  - concurrency cap: 3 simultaneous Claude calls per submission
  - on Promise.allSettled: write awarded + rationale into answer subdoc
        │
        ▼
On all settled successfully:
  gradingStatus='graded'
  apply late penalty if applicable
  call publishHomeworkGrade() if homework.gradebookAutoPublish
On any individual failure:
  still proceed — that question's awarded stays undefined,
  teacher reviews manually
On systemic failure (e.g., Claude API down):
  gradingStatus='failed', errorMessage set, log
        │
        ▼
Client polling sees 'graded' → renders final marks + AI rationale
```

## 11. Late penalty calculation

```ts
function applyLatePenalty(
  submission: IHomeworkSubmission,
  homework: IHomework,
): { mark: number; lateMarkAdjustment?: LateMarkAdjustment } {
  const isLate = submission.submittedAt > homework.dueDate;
  if (!isLate) return { mark: rawMark };

  switch (homework.latePolicy) {
    case 'accept':
      return { mark: rawMark }; // no penalty
    case 'block':
      throw new BadRequestError('Late submissions not accepted');
    case 'penalty': {
      const penaltyPercent = homework.latePenaltyPercent ?? 0;
      const finalMark = rawMark * (1 - penaltyPercent / 100);
      return {
        mark: finalMark,
        lateMarkAdjustment: { rawMark, penaltyPercent, finalMark },
      };
    }
  }
}
```

`block` policy must be enforced at submit time (return 400 before grading runs); `penalty` and `accept` proceed normally and apply at the mark-finalize stage.

## 12. Edge cases & risks

| Risk | Mitigation |
|---|---|
| Comprehension Q generation partially fails | Wrap `Question.insertMany` + homework save in try/catch; on failure delete any inserted Qs |
| Stale Quiz/Resource snapshot | Store `questionSnapshot` per answer at submit time (already in schema) |
| AI grading rate limits | Per-school concurrent grading cap of 30 via in-process semaphore (single-instance only — multi-instance horizontal scaling would need Redis-based locking, deferred). Per-submission concurrency cap of 3 simultaneous Claude calls |
| Concurrent re-submission before grading completes | Submission has `gradingGeneration` counter; new submit increments it. Async grader captures generation at start, checks `submission.gradingGeneration === captured` before each write, aborts silently if the generation has advanced |
| Late-policy=block edge: student submits at 23:59, server processes at 00:01 | Compare `submittedAt` (client-provided) against server time, but accept up to 60s clock skew |
| Teacher edits homework after submissions exist | Bump `homework.version`; submissions show "stale" banner like Module 3 |
| Gradebook publish fails (e.g., assessment cap reached) | Log error, do NOT mark gradingStatus='failed' — grading itself succeeded |
| Parent/student cross-tenant access | All routes filter by `req.user.schoolId` and parent→student link check |

## 14. Acceptance criteria

A teacher can:
1. Open `/teacher/homework/new`, complete the 4-step wizard for each of quiz/reading/exercise, and assign successfully.
2. View `/teacher/homework/[id]` and see all submissions with grading status.
3. Adjust per-question marks and re-publish to gradebook.
4. Re-trigger grading on a submission.

A student can:
1. See "Homework Due" widget on dashboard.
2. Open a homework, see type-specific submission form (no free-text Textarea anywhere).
3. Submit and see deterministic marks instantly.
4. See "Grading..." status and final AI-graded marks within 30s.
5. See late-penalty adjustment applied if applicable.

A parent can:
1. See pending/overdue/awaiting counts per child on dashboard.
2. Open `/parent/homework/[id]` and see child's submission read-only with mark + feedback + AI rationale.

System invariants:
- Zero free-text Textarea submission components in the homework module.
- All backend single-entity finds filter by `schoolId`.
- All files under 350 lines.
- Zero `any` types.
- TypeScript clean: `npx tsc --noEmit` returns nothing in both repos.
- Deterministic grading completes inside the request handler (sync).
- AI grading completes within 30s for typical 5-question homework, no client-side timeout.
